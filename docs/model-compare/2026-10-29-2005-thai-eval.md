  - ใช้ทางสำรอง llama.cpp: `convert_hf_to_gguf.py` (ต้องเปลี่ยนชื่อ `extra_special_tokens` → `additional_special_tokens` ใน `training/fused/tokenizer_config.json` เพราะ mlx-lm บันทึกแบบ transformers รุ่นใหม่ แต่ตัวแปลงใช้ 4.57)
  - Ollama ยัง quantize GGUF ตอนนำเข้าไม่ได้ ("create-time quantization is only supported for safetensors imports") จึง build `llama-quantize` (ติดตั้ง cmake ใน `~/ciel-train`) แล้วย่อเป็น Q4_K_M ก่อน → `ciel-qwen3` 5.0 GB บน llamacpp

## ความเร็ว

- **เวลาในวงเล็บของ `ciel-qwen3` (230–314s) ใช้ไม่ได้:** ระหว่างทดสอบ `qwen3:8b` ถูกถือไว้ใน RAM ตลอด (`keep_alive: -1` ของ Ciel) ทั้งสองโมเดล (~11 GB) + OrbStack (~4 GB) ทำให้ swap หนัก การทดสอบทั้งชุดใช้ ~10 ชั่วโมง (10:25–20:05) ไม่ใช่ 10–15 นาที
- วัดแยกทีละโมเดล (`ollama run --verbose "สวัสดี"` หลัง `ollama stop qwen3:8b`): `ciel-qwen3` **4.23 tok/s** · `qwen3:8b` **4.37 tok/s** → ความเร็วเท่ากัน (สถาปัตยกรรมและ quantize เดียวกัน) ทั้งคู่ต่ำกว่าปกติ (~9–10) เพราะเครื่องใช้ swap อยู่ขณะวัด
- ถ้าจะทดสอบซ้ำ ควรให้ `eval_thai.py` สั่ง unload โมเดลอื่นก่อน (หรือหยุด Ciel ระหว่างทดสอบ) และปิด OrbStack

## คุณภาพภาษาญี่ปุ่นและรูปแบบ (ciel-qwen3@tuned)

- **รูปแบบพัง ❌:** ส่วนใหญ่มีบรรทัดญี่ปุ่นแค่บรรทัดเดียว แล้วซับ `>> 2` ไม่มีประโยคญี่ปุ่นคู่ (แสดงเป็น `[]` —) หรือมีเลขหลุดมาในซับ เช่น "2 ... the best name is", "3 ถ้าเป็นของ…" → ในแอปบรรทัดนั้นจะไม่มีเสียง
- **บรรทัดแรกยาวเกินกฎ:** เช่น `……これは、マスターのためのものでなければなりません。どこで買ったか、忘れてしまいました。` (กฎ ≤ ~12 ตัวอักษร) ทำให้เสียงแรกช้า
- **ภาษาญี่ปุ่นแปลก:** `お仕置きです`, `また、誰かと結びついてしまうのか`, ใช้ 円 กับเงินไทย
- **ซับผิดภาษา:** ถามไทยได้ซับอังกฤษ (ชุด 2)
- **แท็กอารมณ์:** ใช้ได้ แต่บางครั้งไม่เข้ากับเนื้อหา (`[tease]` กับ お仕置き)
- **ลอกประโยคจากข้อมูลเทรน:** grep บรรทัดแรก 8 บรรทัดใน `training/dialogs` เจอแค่คำสั้น `……またですか。` (everyday.yaml) ที่เหลือไม่ตรง ปัญหาหลักคือยังไม่ได้เรียนรูปแบบมากกว่า

## ข้อเสนอ

1. **ยังไม่ควรเปลี่ยนไปใช้ `ciel-qwen3`** แย่กว่า `qwen3:8b` + ตัวอย่างในเกือบทุกชุด และรูปแบบคำตอบพัง (ไม่มีเสียงบางบรรทัด)
2. **ลอง checkpoint อื่นก่อนเทรนใหม่:** นำเข้า checkpoint 300 (val 1.080 แทบเท่า 100 แต่เทรนครบ ~2 รอบข้อมูล) เพื่อดูว่ารูปแบบนิ่งขึ้นไหม ใช้เวลา fuse + แปลง + quantize ~30 นาที ไม่ต้องเทรนใหม่
3. **ข้อมูลเทรน:** 166 คำตอบน้อยเกินไปสำหรับทั้งรูปแบบและความเข้าใจภาษาไทย ชุดที่พลาดทั้งสองโมเดลคือ สรรพนาม (เรา/เธอ/เขา ชุด 1, 5) และความจำข้ามวัน (ชุด 9) ควรเพิ่มบทสนทนาแบบนี้หลายๆ แบบ และใช้ val set ใหญ่ขึ้น (≥ 20 ชุด) จะได้เลือก checkpoint ได้แม่นขึ้น
4. **ทางเลือกที่ไม่ต้องเทรน:** เพิ่มตัวอย่างใน prompt ของ `qwen3:8b` สำหรับเรื่องสรรพนามและ "จำได้แค่ในแชทนี้" (ชุด 7 และ 10 ซึ่ง `qwen3:8b` ทำได้อยู่แล้ว)
