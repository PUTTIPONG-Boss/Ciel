# ช่วงเงียบระหว่างประโยค — v0.3.3 วัดบน Mac 2026-10-27

> ต่อจาก [2026-10-27-1538-latency.md](2026-10-27-1538-latency.md)
> คำถามจากผู้ใช้: หลังเสียงประโยคแรกออก Ciel พูดต่อเนื่องไปเรื่อยๆ ไหม หรือพูดแล้วหยุดรอประโยคถัดไป

## สรุป

- **ยังไม่ต่อเนื่อง:** 3 ใน 4 ข้อเงียบ **0.9–2.8 วินาที** ระหว่างประโยคแรกกับประโยคที่สอง
- **"เสียงครบ 8.2s" ในรายงาน latency คือเวลาที่ไฟล์เสียงสุดท้ายส่งมาถึง** ไม่ใช่เวลาที่พูดจบ เวลาพูดจบจริงอยู่ที่ 10.7–21.2 วินาที

## วิธีวัด

ต่อ WebSocket แบบเดียวกับ `scripts/measure_latency.py` (login, `speak: true`) แล้วถามต่อเนื่อง 4 ข้อ จากนั้นจำลองการเล่นเสียงแบบเดียวกับมือถือ:

- ประโยคหนึ่งเริ่มเล่นเมื่อ **เสียงมาถึงแล้ว และประโยคก่อนหน้าเล่นจบแล้ว**
- ความยาวเสียงประมาณจากขนาดไฟล์ MP3 ของ edge-tts (48 kbit/s ≈ 6,000 byte/วินาที)

## ผล

| คำถาม | ประโยค 1 มาถึง → เล่น | ประโยค 2 มาถึง → เล่น | เงียบระหว่างกลาง | พูดจบ |
|---|---|---|---|---|
| วันนี้เหนื่อยมากเลย งานเยอะ | 4.0s → 4.0–6.2s | 7.0s → 7.0–10.7s | **0.9s** | 10.7s |
| ช่วยอธิบายว่า RAM กับ SSD ต่างกันยังไง | 4.3s → 4.3–9.3s | 12.0s → 12.0–21.2s | **2.8s** | 21.2s |
| ลืมกินข้าวเย็นอีกแล้ว | 5.0s → 5.0–6.8s | 6.2s → 6.8–11.9s | 0 | 11.9s |
| What should I name my new cat? | 3.4s → 3.4–5.7s | 7.9s → 7.9–12.5s | **2.2s** | 12.5s |

## สาเหตุ

โมเดลเขียนคำตอบสลับบรรทัด: ญี่ปุ่น 1 → `>>` คำแปล 1 → ญี่ปุ่น 2 → `>>` คำแปล 2

1. ประโยคแรกถูกบังคับให้สั้น (≈12 ตัวอักษร) เพื่อให้ผ่านเป้า 4 วินาที จึง **พูดจบใน ~2 วินาที**
2. ระหว่างนั้นโมเดลต้องเขียน **คำแปลไทยของประโยคแรก** ให้จบก่อน ภาษาไทยใช้ token เยอะ ~20–30 token = **2–3 วินาที** ที่ ~10 tok/s
3. จากนั้นยังต้องเขียนประโยคญี่ปุ่นที่ 2 (~1–1.5s) แล้วรอ TTS (~1s)

เวลาที่ใช้กว่าเสียงประโยคที่ 2 จะพร้อม (~4–5s) จึงนานกว่าความยาวเสียงประโยคแรก (~2s) จนเกิดช่วงเงียบ
ข้อ "ลืมกินข้าว" ไม่เงียบเพราะประโยคแรกยาวพอ (`……やっぱり。` + เสียงมาถึงช้า) และประโยคที่ 2 มาเร็ว

## ข้อเสนอแก้ (ฝั่ง Windows)

1. **เขียนประโยคญี่ปุ่นทั้งหมดก่อน แล้วค่อยเขียนคำแปล** (แนะนำ ได้ผลมากสุด)
   - รูปแบบ เช่น:
     ```
     [concern]……お疲れです。
     早めに休んでください。
     >> ...เหนื่อยมากเลยนะคะ
     >> พักผ่อนให้เร็วหน่อยนะคะ
     ```
   - ประโยคญี่ปุ่นที่ 2 จะตามมาหลังประโยคแรกแค่ ~1–1.5s ซึ่งสั้นกว่าเวลาพูดประโยคแรก เสียงจึงต่อกันได้
   - ซับจะขึ้นช้ากว่าเสียงเล็กน้อย ฝั่งเว็บต้องจับคู่ `>>` ลำดับที่ n กับประโยคที่ n (แก้ `AnimeStream` ใน `ciel/speech.py` ให้เก็บคิวประโยคที่ยังไม่มีคำแปล แทน `self.translated` ตัวเดียว)
   - ต้องแก้ `anime_rules` / ตัวอย่างใน `persona/ciel.yaml` ให้เป็นรูปแบบนี้ทั้งหมด เพราะโมเดลเลียนรูปแบบจากตัวอย่าง
2. **ถ้ายังสลับบรรทัดแบบเดิม:** ให้ประโยคที่ 2 สั้น และคำแปลสั้น หรือให้วงกลมแสดงท่า "กำลังคิด" ระหว่างรอ
   (เงียบ ~1s ยังดูเป็นธรรมชาติ แต่ 2–3s จะรู้สึกสะดุด)
3. **ปรับรายงาน `measure_latency.py`:** เพิ่มคอลัมน์ "พูดจบจริง" และ "เงียบรวมระหว่างประโยค" โดยใช้วิธีจำลองการเล่นข้างบน จะได้ไม่สับสนกับ "เสียงครบ" ที่เป็นเวลาเสียงมาถึง

ยังไม่ได้วัดว่าหลังแก้แล้วช่วงเงียบหายจริง ต้องวัดซ้ำหลังฝั่ง Windows push
