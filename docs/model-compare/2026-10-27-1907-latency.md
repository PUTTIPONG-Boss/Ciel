### ข้อแรกช้าเพราะอะไร

- **ไม่ใช่ cache หาย:** llama.cpp บอกว่าข้อแรก `cached n_tokens = 3615` ต้องอ่านใหม่แค่ **40 token** เท่ากับข้ออื่น warm-up ทำงานถูกต้อง
- **แต่ 40 token นั้นใช้ 2.17s (54 ms/token)** ขณะที่ข้ออื่นใช้ 12–15 ms/token
  แปลว่าเป็น **คำขอขนาดเล็กครั้งแรกหลังเซิร์ฟเวอร์เริ่ม** GPU (Metal) ยังไม่เคยรันขนาดนี้ จึงเสียเวลาเตรียมครั้งแรก
  warm-up ตอนนี้ทำแค่อ่าน prompt ก้อนใหญ่ (batch 512) + สร้าง 1 token จึงไม่ได้อุ่นกรณี "อ่านข้อความสั้นๆ ต่อท้าย cache"
- ยืนยัน: ทดลองยิงตรงกับ Ollama ด้วย `_payload` ของแอป หลังจาก GPU อุ่นแล้ว warm-up → ข้อความแรก (`สวัสดี Ciel`) ใช้ prefill **0.62s** (ไม่ช้า)

**ข้อเสนอ:** ใน `warmup()` ยิงคำขอที่สองต่อจากครั้งแรก ด้วย `build_messages([ข้อความ user ที่ stamp แล้ว เช่น "สวัสดี"])` และ `num_predict` ~4
จะได้อุ่นการอ่านข้อความสั้นและการสร้าง token ไว้ก่อน (เสียเวลาตอนเริ่มเซิร์ฟเวอร์ ~1–2s) คาดว่าข้อแรกจะลดจาก 4.4s เหลือ ~3s ซึ่งยังไม่ได้วัด

### ตัวเลข `ollama: prefill N tok` ใน log ไม่ใช่ token ที่ไม่ได้มาจาก cache

`prompt_eval_count` ของ Ollama คือ **ความยาว prompt ทั้งหมด** ไม่ใช่ส่วนที่ไม่ได้มาจาก cache ทดลองส่ง prompt เดิมซ้ำทั้งก้อน (cache hit 100%) ก็ยังได้ 3655 แต่เวลาเหลือ 0.11s
คอมเมนต์ใน `ciel/llm.py` (`prompt_eval_count = prompt tokens NOT found in the cache`) จึงไม่ถูก ให้ดู**เวลา** prefill แทน หรือดู `cached n_tokens` ใน `~/.ollama/logs/server.log`
