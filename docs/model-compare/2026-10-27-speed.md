# ทำให้ Ciel ตอบเร็วขึ้น — วัดบน Mac 2026-10-27

> เครื่อง M1 16GB · `qwen3:8b` · วัดผ่าน `/api/chat` ของ Ollama ด้วย prompt จริงจาก `PersonaStore.build_messages`
> สรุป: **เวลาส่วนใหญ่ไม่ได้หมดไปกับการคิดคำตอบ** แต่หมดไปกับการอ่าน prompt ยาว ~3,000 token ใหม่ ซึ่งเลี่ยงได้ด้วยการแก้โค้ด 2 จุด

## เวลาหมดไปกับอะไร

| สถานการณ์ | โหลดโมเดล | อ่าน prompt (prefill) | สร้างคำตอบ | รวม |
|---|---|---|---|---|
| ข้อความแรกหลังไม่ได้ใช้เกิน 5 นาที (Ollama ปล่อยโมเดลออกจาก RAM แล้ว) | 3.8s | **29.7s** | 9.5s | **43s** |
| ข้อความถัดไป ห่างกันเกิน 1 นาที | 0 | **11.0s** | 7.2s | **18s** |
| ข้อความถัดไป ภายในนาทีเดียวกัน | 0 | 0.4s | 8.7s | 9s |

- อ่าน prompt ได้ประมาณ 100–300 token/วินาที แต่ prompt ของ Ciel (นิสัย + ตัวอย่าง 10 ชุด) ยาว ~3,000 token
- สร้างคำตอบได้ประมาณ **10 token/วินาที** (ภาษาญี่ปุ่นกับไทยใช้ token เยอะ)
- Ollama จำ prompt ที่อ่านแล้วไว้ (prompt cache) แต่ใช้ได้เฉพาะส่วนต้นที่ไม่เปลี่ยน

## สาเหตุที่ 1: นาฬิกาใน system prompt ทำให้ cache ใช้ไม่ได้ (เสีย ~10 วินาทีทุกข้อความ)

`Persona.system_prompt()` ใส่ `เวลา HH:MM น.` ไว้ใน system prompt ซึ่งอยู่**ก่อน**ตัวอย่างบทสนทนาทั้งหมด
พอเวลาเปลี่ยนแม้แค่ 1 นาที Ollama ต้องอ่านทุกอย่างหลังจุดนั้นใหม่ (~3,000 token) ในการใช้งานจริงข้อความมักห่างกันเกิน 1 นาที จึงเสียเวลานี้แทบทุกข้อความ

**ทดลองย้ายเวลาไปไว้ในข้อความล่าสุดของผู้ใช้:**

| | อ่าน prompt | รวม |
|---|---|---|
| เวลาอยู่ใน system prompt (ตอนนี้) · ข้อความห่าง 1 นาที | 9.4s | 12.1s |
| เวลาอยู่ในข้อความผู้ใช้ · ข้อความห่าง 1 นาที | **0.4s** | **2.5s** |
| เวลาอยู่ในข้อความผู้ใช้ · ข้อความห่าง 7 นาที | **0.6s** | **7.7s** |

(ทดลองด้วยนิสัยแบบพูดน้อย [ciel-concise-proposal.yaml](ciel-concise-proposal.yaml))
ลองย้ายไปเป็น system message แยกหลังตัวอย่างแล้ว **ไม่ช่วย** (ยัง 8.5s) น่าจะเพราะ chat template ของ Qwen3 รวม system message ไว้ด้านบน ต้องใส่ในข้อความผู้ใช้เท่านั้น

**แก้ที่ `ciel/persona.py`:**
- เอาส่วน `# ข้อมูลตอนนี้` ออกจาก `system_prompt()`
- ใน `build_messages()` เติมเวลาไว้หน้าข้อความ user **ตัวสุดท้าย** เท่านั้น เช่น `"(วันจันทร์ที่ 27/10/2569 เวลา 12:01 น.)\nเธอน่ารักนะ"`
  อย่าเก็บข้อความที่เติมเวลานี้ลง `history` ข้อความเก่าจะได้ไม่เปลี่ยน และ cache ใช้ต่อได้

## สาเหตุที่ 2: Ollama ปล่อยโมเดลทิ้งหลังไม่ได้ใช้ 5 นาที (เสีย ~35 วินาที)

ค่าเริ่มต้นของ Ollama คือ `keep_alive` 5 นาที พอโมเดลหลุดจาก RAM ข้อความถัดไปต้องโหลดโมเดลใหม่และอ่าน prompt ใหม่ทั้งหมด ~43 วินาที
Ciel เปิดทิ้งไว้เป็นเซิร์ฟเวอร์อยู่แล้ว และ RAM 16GB พอให้ถือโมเดล 5GB ไว้ตลอด

**แก้ที่ `ciel/llm.py`:**
- เพิ่ม `"keep_alive": -1` ใน payload ของ `/api/chat` (หรือทำเป็นค่าใน `.env` เช่น `CIEL_KEEP_ALIVE=-1`)
- ตอนเซิร์ฟเวอร์เริ่ม (รวมถึงหลังระบบอัปเดตรีสตาร์ท) ให้ยิงคำขอ warm-up 1 ครั้งด้วย `build_messages([])` ของนิสัยปัจจุบัน และ `"options": {"num_predict": 1}`
  prompt จะเข้า cache ก่อนผู้ใช้พิมพ์ข้อความแรก

## สาเหตุที่ 3: คำตอบยาว

สร้างคำตอบได้แค่ ~10 token/วินาที ทุก token จึงมีผล นิสัยแบบพูดน้อยลดคำตอบจาก ~90 → ~30–60 token (เร็วขึ้น 3–6 วินาที)
ดู [2026-10-27-concise-prompt.md](2026-10-27-concise-prompt.md)
